# 纯前端抽奖页设计

## 目标

为现有 React + Vite 案例站新增 `/topics/lucky-draw` 页面，让同一台设备上的参与者依次领取 1、2、3…号，并让主持人从当前已领取号码范围内随机抽出一个号码。

## 约束

- 纯前端，不接接口，不新增依赖。
- 数据保存在当前浏览器 `localStorage`；不同设备之间不会同步。
- 页面保持两个清晰功能区：领取号码牌、随机开奖。
- 先交付可部署的简单版本，便于后续 backcoding 调整视觉和逻辑。

## 方案比较

1. **浏览器本地号码池（采用）**：点击领号即顺序增加号码，开奖从 `1..已领取人数` 随机选择。最贴合纯前端约束，适合活动现场共用一台设备。
2. **手动输入参与人数**：主持人输入 80 后直接开奖。实现最简单，但缺少用户要求的“领取号码牌”流程。
3. **跨设备共享号码池**：需要后端或实时数据库，能支持每位参与者使用自己的手机，但超出本次纯前端范围。

## 交互与状态

- 领号按钮每次发放下一个连续号码，并显示最近领取号码。
- 开奖按钮在无人领号时禁用；有 80 人时结果严格落在 1 到 80。
- 新号码加入后清除旧的中奖结果，避免旧结果被误认为当前号码池的开奖结果。
- 重置按钮清空当前浏览器中的号码池和开奖结果。
- 号码与开奖结果通过 `aria-live` 向辅助技术播报，并尊重减少动效设置。

## 视觉方向

采用明亮的活动现场风格：暖白背景、深紫正文、橙色行动按钮、两张大功能卡。号码使用高对比的大号等宽数字；装饰图形只服务于“号码牌”和“开奖焦点”，不引入图片资产。
