# Remotion Course Workbench Story

## Persona

- 角色：29 岁互联网女性，偏产品/工具型创作者。
- 口吻：生活化分享，不像技术汇报；但有清楚的产品设计思路。
- 气质：不是在炫技，而是在讲“我怎么把一个很麻烦的内容生产流程，拆成一个能复用的小工具”。
- 观众感受：看完知道这个工具能做什么、为什么这么设计、自己以后怎么用。

## Storyline

1. 先给结果：这是一个给口播课程视频加动画的制作台。
2. 讲产品设计动机：目标不是剪一条片，而是把“PPT 背景、真人口播、教学标注、时间轴、导出包”拆成稳定能力。
3. 讲工作流设计：从项目复盘到 PPT 视频、口播文案、用户录制、工作台合成，过程中要允许人工微调。
4. 讲实际使用：导入 HyperFrames 项目，上传横屏口播，点选元素，绑定红圈/高亮/箭头。
5. 讲实现边界：管理台操作框不进成片，PPT 自带动画不重复导出，新增标注才是 overlay。
6. 讲最终价值：它不是一次性视频，而是后续做开发/学习 topic 复盘视频的生产工具。

## Voiceover Script

**[0-8s]**
先给你看一下结果。我最近做了一个小工具，专门给口播课程视频加动画。[停] 以后我录一段横屏口播，放在右下角，PPT 在后面播，重点内容再用红圈、高亮标出来。

**[8-20s]**
我一开始想清楚的第一件事是：这不是剪一条视频，而是要做一个制作台。[停] 因为我后面会反复做这种内容，不能每次都从零开始拖素材、调位置、对时间轴。

**[20-34s]**
所以我先把产品能力拆开。后台是 HyperFrames 生成的 PPT 视频，前台是我自己录的口播，第三层才是教学标注，比如圈标题、强调关键句、提示下一步。[停] 这几层分开，后面才好维护。

**[34-50s]**
然后我又把完整工作流顺了一遍：先让 agent 复盘一个真实项目，再生成 PPT 分享视频；接着根据视频时长写口播稿，我自己录完以后，再把口播和 PPT 放进这个工作台里合成。

**[50-66s]**
真正使用的时候，我希望它像一个很轻的剪辑前台。导入项目以后，直接在画面里点标题、点代码块、点重点区域，然后给这个元素绑定红圈、高亮或者箭头。[停] 不用一帧一帧手动对。

**[66-82s]**
做到这里我才发现，有些边界必须提前设计好。比如页面里的蓝色选择框只是给我操作用的，它不能出现在成片里；PPT 里原本就有的动画，也不要再拆出来重复加。

**[82-98s]**
最后我把它定成三类东西：PPT 视频只当背景素材，管理台控件只负责编辑，我新加的红圈、高亮、箭头才进入导出。[停] 这样不管是直接出成片，还是交给剪映继续改，都比较干净。

**[98-110s]**
我现在觉得这条链路挺适合做开发复盘、学习笔记和训练营课程。它不是替我一次性做完视频，而是把我每次都会重复做的那一套流程，变成了一个可以继续迭代的小工具。

## Recording Guidance

- 推荐语速：230-250 字/分钟，偏自然分享，不要播音腔。
- 前 20 秒重点讲“为什么要做制作台”，不要急着讲 bug。
- 第 20-50 秒讲产品设计过程，可以稍微慢一点，让观众听清“后台、前台、标注层、工作流”。
- 第 50 秒之后讲怎么用，语气更像在带朋友看一个工具。
- 技术词尽量用生活化解释承接，例如“overlay”可以说成“我后面新加的标注层”。
- 右下角会放横屏口播，录制时保持自然坐姿，看镜头即可。

## Opening Hook Options

1. “我最近做了一个小工具，专门解决口播教程视频里最麻烦的动画标注。”
2. “以前我做这种教程视频，每次都要重新拖素材、对时间轴，现在我想把它做成一个制作台。”
3. “这条视频不是重点，重点是我把做这类视频的流程拆成了一个能复用的工具。”

## Style Notes

- 主线：产品设计过程 > 怎么使用 > 实现边界。
- 弱化“导出翻车”的戏剧冲突，只把它当作为什么要分清边界的例子。
- 视觉风格可以更科技：深色网格、冷蓝/青绿光、数据面板感，但口播要保持生活化。
